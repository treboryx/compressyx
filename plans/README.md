- 003 and 004 are independent of everything and of each other. Either can go first.
- 005 depends on 003 because 003 establishes `FileUtils.expand(urls:)` as the

## Direction findings not yet planned

- **Target-size mode ("fit under N MB")** (M–L). Users think in Discord/email
  attachment limits, not quality presets. Requires a two-pass bitrate
  calculation for video; images can binary-search quality.
- **Bundle ffmpeg + pngquant + cwebp instead of requiring Homebrew** (L). The
  tool-finding code probes hardcoded Homebrew paths, so the app is unusable for
  anyone without Homebrew — the biggest adoption blocker for a signed, notarized
  app aimed at non-developers. **Carries a real licensing tradeoff**: ffmpeg is
  LGPL/GPL depending on build flags, and this repo is MIT. Needs a licensing
  decision before any implementation plan is written. **No longer blocks plan
  005** — the Services route runs in-process, so the Homebrew question never
  arises there.
- **Establish a test baseline** (M). There is no `Tests/` directory and no test
  target; `xcodebuild build` is the only verification gate. Every plan here is
  riskier than it needs to be because of this. The purest unit-test candidates
  as of `5c5f8b8`: `FileUtils.expand`, `ImageCompressor.resolve_format`,
  `VideoResolution.max_height`, `AudioHandling.ffmpeg_args`.

## Defects found, not yet planned

Surfaced during the 2026-08-23 `next` audit. Recorded so they are not re-derived.

- **No floor on output size; growth is labelled as savings.** VERIFIED. Nothing
  compares output to input. Measured at `5c5f8b8`: a Display-P3 JPEG at the
  default *High* preset grew 34,564 → 41,483 bytes (+20%); at *Highest* it grew
  to 119,270 (+245%). A real system JPEG at *Highest* went 63,004 → 64,010.
  `FileRowView.swift:53` then renders this as `(-245% smaller)`. Not universal —
  the same system JPEG at *High* compressed 64% — but unguarded. Fix is small:
  keep whichever file is smaller, label it "already optimal". **This is the
  highest-leverage unplanned item; a compression tool that returns a larger file
  and calls it savings is the one bug that costs trust.**
- ~~**WebM output fails for any input with AAC audio.**~~ **FIXED during plan 006
  execution.** Now execute-verified rather than suspected: `-c:v libvpx-vp9 -c:a copy`
  on an AAC source exits 234 with "Conversion failed!", while `-c:a libopus` exits 0.
  `AudioHandling.ffmpeg_args(webm:)` now selects Opus for WebM containers. Deviation
  from plan 006's scope, taken deliberately — see Execution notes.
- ~~**cwebp missing from the main-window dependency check.**~~ **FIXED during
  plan 006 execution** — one-line addition alongside the sidebar work.
- **Output paths are flat and can collide.** Two files named `shot.jpg` in
  different folders both become `shot_compressed.jpg`; with a custom output
  folder the second overwrites the first. Pre-existing for multi-select, but
  plan 003 makes it much easier to hit.

## Execution notes

- **001**: `didSet` fires during `init` under the `@Observable` macro, contrary to
  plain-Swift property-observer semantics. Harmless (the restore rewrites the value
  it just read); the plan text was corrected.
- **002**: the plan declared `CompressionSettings.swift` out of scope on the
  assumption that the output *path* was already correct. It was not — for TIFF/BMP
  inputs with "Same as input" selected, `output_url` kept the `.tiff` extension while
  the encoder wrote JPEG. Fixed by routing the fallback through the new
  `FileUtils.same_as_input_extension(for:)`, so the extension and the encoder agree
  in one place. Verified 20/20 input×target combinations with `file(1)`.
- **WebP output** (follow-up, maintainer-approved): the plan deferred this pending a
  dependency decision. ImageIO on macOS 26 cannot write WebP
  (`CGImageDestinationCopyTypeIdentifiers()` has no `org.webmproject.webp`), so there
  is no dependency-free path. Implemented via `cwebp` (`brew install webp`), matching
  the existing pngquant shell-out pattern. Dependencies tab gained a cwebp row, an
  "Install All Missing" button, and a Homebrew-absent state; brew logic moved to
  `Utils/Dependencies.swift`. Re-verified 20/20 with WebP now succeeding from every
  input, including HEIC via the PNG transcode.
- **003**: implemented as written. `FileUtils.expand` verified against a fixture tree —
  recursion, hidden-file skipping, `.txt` exclusion, `.app` packages not descended,
  empty folders safe, single loose files unchanged.
- **004**: two deviations, both forced by measurement. (a) The plan's Step 4 allowed
  PNG preservation to be impossible; it is — `pngquant` discards ancillary chunks and
  PNG has no EXIF container — so PNG output is documented as always metadata-free
  rather than faked. (b) WebP initially preserved nothing because `compress_webp`
  routed every input through the `png_source` transcode, destroying EXIF before cwebp
  could copy it; readable formats now pass through untouched. A third issue surfaced
  in testing: cwebp's `-metadata` is all-or-nothing over EXIF and GPS lives inside it,
  so *Remove location* leaked coordinates. Fixed with `gps_stripped_copy`, which uses
  `CGImageDestinationAddImageFromSource` + `kCFNull` to drop the GPS dictionary without
  re-encoding. Full 9-cell policy matrix and an 8-case orientation matrix verified with
  `exiftool` and `sips`.
- **006**: deviated from its own Scope section to fix the `-c:a copy` WebM bug. The
  justification: the fix lands inside `AudioHandling`, the very type the plan
  introduces, and shipping new video controls on top of a container that cannot
  produce output at all would have been indefensible. All 6 mp4 rows and 4 webm rows
  verified with `ffprobe`, including the no-upscale guard (720p source, "4K" target,
  output stays 1280×720) and even-width rounding (854×480).
- **005**: see `005-findings.md`. Headline: `NSServices` registers with no new target,
  which moots the framework split and the extension-sandbox risk entirely.

## Findings considered and rejected

- *Output filename collision* (`x_compressed.png` re-run produces
  `x_compressed_compressed.png`): cosmetic, self-limiting, and the current
  behavior is arguably safer than silently overwriting. Not worth a plan.
- *ICC colour profiles are stripped during compression*: **tested and false.**
  A Display P3 JPEG round-tripped through `compress_jpeg` at `5c5f8b8` retained
  its profile (`sips -g profile` → `Display P3`). Only EXIF is lost, which is
  plan 004. Do not re-audit.
- *The app always inflates already-compressed images*: **tested and false.** A
  real system JPEG compressed 64% at the *High* preset. The defect is the
  missing floor, not universal inflation — see the defects section above.
- *ffmpeg was not installed on the audit machine*: **wrong, and the error was
  mine.** The probe was `ffmpeg -encoders | grep -i webp`, which exited non-zero
  because this ffmpeg build has no WebP encoder — not because ffmpeg was absent.
  ffmpeg 9.0.1 was installed all along. The claim propagated into plan 006's
  Commands section and the audit summary before being caught.
- *Standalone "resize / max-dimension" direction finding* (recorded earlier on
  2026-08-23): superseded by plan 006, which folds resolution into one video
  panel with audio and fps rather than shipping two overlapping features.
