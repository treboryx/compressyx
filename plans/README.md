## Direction findings not yet planned

Awaiting maintainer selection — see the audit summary. Listed here so they are
not re-derived on the next run.

- **Resize / max-dimension control** (M). Downscaling is the single largest
  real-world size win for screenshots and screen recordings, and the app has no
  scale option at all. `ffmpeg -vf scale` for video, `NSImage` redraw for stills.
- **Target-size mode ("fit under N MB")** (M–L). Users think in Discord/email
  attachment limits, not quality presets. Requires a two-pass bitrate
  calculation for video; images can binary-search quality.
- **Bundle ffmpeg + pngquant instead of requiring Homebrew** (L). Currently
  `VideoCompressor.find_ffmpeg` probes three hardcoded Homebrew paths and
  Settings offers a `brew install` button, so the app is unusable for anyone
  without Homebrew — the biggest adoption blocker for a signed, notarized app
  aimed at non-developers. **Carries a real licensing tradeoff**: ffmpeg is
  LGPL/GPL depending on build flags, and this repo is MIT. Needs a licensing
  decision before any implementation plan is written.
- **Establish a test baseline** (M). There is no `Tests/` directory and no test
  target; `xcodebuild build` is currently the only verification gate. Every plan
  above is riskier than it needs to be because of this.

## Execution notes

- **001**: `didSet` fires during `init` under the `@Observable` macro, contrary to
  plain-Swift property-observer semantics. Harmless (the restore rewrites the value
  it just read); the plan text was corrected.
- **002**: the plan declared `CompressionSettings.swift` out of scope on the
  assumption that the output *path* was already correct. It was not — for TIFF/BMP
  inputs with "Same as input" selected, `output_url` kept the `.tiff` extension while
  the encoder wrote JPEG. Fixed by routing the fallback through the new
  `FileUtils.same_as_input_extension(for:)`, so the extension and the encoder agree
  in one place. Verified 20/20 input×target combinations with `file(1)`.
- **WebP output** (follow-up, maintainer-approved): the plan deferred this pending a
  dependency decision. ImageIO on macOS 26 cannot write WebP
  (`CGImageDestinationCopyTypeIdentifiers()` has no `org.webmproject.webp`), so there
  is no dependency-free path. Implemented via `cwebp` (`brew install webp`), matching
  the existing pngquant shell-out pattern. Dependencies tab gained a cwebp row, an
  "Install All Missing" button, and a Homebrew-absent state; brew logic moved to
  `Utils/Dependencies.swift`. Re-verified 20/20 with WebP now succeeding from every
  input, including HEIC via the PNG transcode.
